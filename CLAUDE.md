# Правила репозитория devuz-os

Здесь живут рецепты сборки DevUz OS — системы для мини-ПК «DevUz Box».
Эти правила обязательны для каждой сессии Claude и для людей.

## Язык

- Документы, README, описания PR и сообщения коммитов — на русском,
  простыми словами. Термины (mkosi, UKI, erofs) можно оставлять как есть,
  но объяснять при первом упоминании.
- В тексты, комментарии и коммиты не писать идентификаторы моделей ИИ.

## Как работаем

- Ветка по умолчанию — `main`. Прямо в `main` не пушим: каждое изменение —
  через PR.
- Свой PR сливаем способом squash сразу, как только сборка в GitHub Actions
  зелёная (решение владельца: «Сливай на автомате всегда, не спрашивай»).
  Красную сборку не сливаем никогда; тесты не отключаем и не пропускаем,
  чтобы стало зелёным.
- Критерий готовности — зелёный Actions, а не сборка на своей машине.

## Что нельзя класть в репозиторий

Репозиторий открытый. В нём никогда не бывает:

- ключей и секретов — ни боевых, ни тестовых закрытых (тестовые ключи
  генерируются на лету в Actions и никуда не сохраняются);
- паролей, токенов, `mkosi.key`, `mkosi.crt`, `mkosi.rootpw`;
- цен поставщиков, себестоимости, данных клиентов.

## mkosi

- Версия mkosi — одна на весь репозиторий: **v27.1**. Она записана в
  `README.md` и в `.github/workflows/build.yml`; меняем в обоих местах сразу.
- Каждую опцию mkosi сверяем с man **именно этой версии**
  (`mkosi/resources/man/mkosi.1.md` на теге). Конфиги ParticleOS — только
  как пример: они живут на mkosi с ветки main и на systemd новее 257.
  Если нужной опции в нашей версии нет — записываем это в отчёт недели,
  а не тянем mkosi с main.

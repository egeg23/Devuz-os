# Неделя 5: «Ядро» — шлюз моделей, первый кусок API платформы

Старт — 03.11.2026, слово владельца: «Да, делаем и двигаемся дальше».
Цель из дорожной карты (`06-roadmap.md` студии, часть А) и
`02-architecture.md` (раздел 4 «Ядро»), с поправкой на
[platform.md](platform.md): API «Ядра» — первый кусок API платформы для
магазина, поэтому сразу с версиями и правами.

**Проверяемый результат недели**: тест в Actions — приложение с токеном
получает ответ модели через «Ядро» (`/v1/chat/completions`); приложение без
права на задачу получает отказ; модель с неверной подписью не
загружается; живой запрос проходит раньше ночного. На облачной машине с
NVIDIA — тот же код отвечает большой моделью, замеры ток/с записаны.

## Задачи

| № | Что | Готово, когда |
|---|---|---|
| 1 | «Ядро» v1: служба на Node без пакетов (основа — `lib/llm/route.ts`, `openai-compat.ts` студии), OpenAI-совместимый API на `127.0.0.1`, маршрут по задаче (`chat`, `chat-uz`, `code`, `embed`, `stt`…), подписанный контейнер в `/usr`, под сторожем | тест: запрос `chat` → ответ |
| 2 | Токены приложений с правами: какие задачи, лимиты; учёт (кто, задача, токены, время); облако выключено | тест: без права — 403; учёт пишется |
| 3 | Модели: каталог `/var/lib/devuz/models`, подписанный манифест (имя, версия, лицензия, sha256 файлов); в Actions — маленькая модель на процессоре (llama.cpp) | тест: модель с битой подписью или хешем не загружается |
| 4 | Очередь с приоритетами: живой > чат > сотрудник > ночные | тест: живой запрос не ждёт ночных |
| 5 | Облачная машина с NVIDIA: vLLM + gpt-oss-120b, faster-whisper, bge-m3 + Qdrant; «Ядро» ходит к ней | замеры ток/с в отчёте; **нужен аккаунт облака** (вопрос владельцу) |
| 6 | Расширение NVIDIA (sysext): открытые модули под наше ядро, подпись модулей, verity с подписью (там же — задача 4 недели 3) | расширение собирается в Actions и проверяется подпись; грузить — на облачной машине |
| 7 | Отчёт `docs/week-05.md` | файл в `main` |

## Решения на старте

- «Ядро» — своя служба на Node без пакетов, как в архитектуре; в тесте —
  `llama-server` (llama.cpp, MIT) с маленькой моделью на процессоре, чтобы
  всё проверялось в Actions без GPU.
- API — версии с первого дня (`/v1`); токен приложения — с правами по
  задачам: это та же схема, что потом у приложений магазина.
- Веса моделей — не в `/usr` (десятки ГБ): `/var/lib/devuz/models`,
  подписанный манифест; маленькая тестовая модель — только в тесте.

## Риски

| Риск | Что делаем |

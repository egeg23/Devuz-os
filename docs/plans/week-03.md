# Неделя 3: Secure Boot, подписи, шифрование диска

Старт — 02.11.2026, слово владельца: «Погнали неделя 3». Цель из дорожной
карты (`06-roadmap.md` студии, часть А) и раздела 04-security.

**Проверяемый результат недели**: тесты в Actions —
подменённый UKI не грузится; диск с данными открывается сам (TPM) и после
обновления тоже; с чужим загрузчиком — не открывается; ключ восстановления
открывает.

## Задачи

| № | Что | Готово, когда |
|---|---|---|
| 1 | `docs/status.md` — короткая памятка для любой сессии | файл в `main`, правило в `CLAUDE.md` |
| 2 | Тесты без строки ядра: самопроверка и тест обновления включаются учётными данными (`io.systemd.credential` через SMBIOS, `ConditionCredential=`), а не `systemd.wants=` | все тесты недели 2 зелёные на новом способе |
| 3 | Secure Boot: `SecureBoot=yes` (UKI и systemd-boot подписаны тестовым ключом на лету), в тесте `Firmware=uefi-secure-boot` + `FirmwareVariables=custom` (наш сертификат в OVMF) | самопроверка видит `SecureBoot enabled`; ручной режим `unsigned-uki` (UKI без подписи) — не грузится |
| 4 | Подпись корня хеша проверяется ядром: сертификат verity в UKI (`.pcrpkey`/keyring), `usrhash` + `usr-verity-sig` | ручной режим: подпись verity чужим ключом — не грузится |
| 5 | Подписанные обновления: `SHA256SUMS.gpg` тестовым ключом GPG, ключ в образе (`/usr/lib/systemd/import-pubring.pgp`), тест без `--verify=no` | тест A→B зелёный с проверкой подписи; неподписанный `SHA256SUMS` — обновление отклонено |
| 6 | Root при первой загрузке: в образе только ESP + `/usr`; `systemd-repart` создаёт root (LUKS2) при первом запуске, `/etc` — из `/usr/share/factory` + `tmpfiles.d`; закрыть находки разведки недели 1 (`alternatives`, мастер первой загрузки, PAM) | образ без root-раздела проходит все тесты |
| 7 | LUKS2 + TPM (swtpm): ключ root запечатан на подписанную политику PCR 11 (`SignExpectedPcr=`, `systemd-measure`) + PCR 7; ключ восстановления | тест: после перезагрузки диск открывается сам; после обновления A→B — тоже; с другим ключом Secure Boot — не открывается, ключ восстановления открывает |
| 8 | Отчёт `docs/week-03.md` | файл в `main` |

## Порядок

1 → 2 → 3 → 4 → 5 → 6 → 7. Каждое — отдельным PR со своим тестом.
6 и 7 тесно связаны (root создаётся сразу зашифрованным) — возможно, один PR.

## Риски

| Риск | Что делаем |
|---|---|
| Под Secure Boot systemd-stub не берёт строку ядра из SMBIOS | задача 2 — учётные данные вместо строки ядра, до включения Secure Boot |
| Учётные данные SMBIOS могут не читаться под Secure Boot | проверяем в задаче 3; запасной путь — отдельный тестовый UKI-профиль (`UnifiedKernelImageProfiles=`) |
| swtpm без AES-128-CFB (как с pcrlock на неделе 1) — `systemd-cryptenroll --tpm2` может не работать | проверяем первым делом в задаче 7; если так — свой swtpm из tools tree или другая сборка libtpms |
| Пустой `/etc` в Debian (alternatives, PAM) | список из разведки недели 1, по одному пункту, тест «command not found» уже краснеет |
| Опции systemd 257 / mkosi v27.1 отличаются от ParticleOS | сверяем с man своих версий, расхождения — в отчёт |

# Неделя 6: «Офис» v0 — визуальная оболочка коробки

Старт — 03.11.2026, слово владельца: «Да, погнали. Делаем. Параллельно можно
и визуальную оболочку начинать делать». Цель из дорожной карты студии
(`06-roadmap.md`, часть А): «Офис» v0 — единое окно, ИИ-сотрудник на
локальной модели, чат по документам.

**Проверяемый результат недели**: сообщение в тестовый Telegram-бот →
ответ локальной модели через «Ядро» → карточка в «Офисе» в браузере
(`https://devuz.local`). Часть, которую можно проверить без интернета, —
тест в Actions: «Офис» поднимается на коробке, открывается через Caddy,
вход по паролю, чат с ИИ отвечает через «Ядро».

## Где что живёт

«Офис» — наш продукт, его код в **закрытом** репозитории (решение плана
студии, `README.md`; владелец создаёт репозиторий, 03.11). Здесь, в
открытом `devuz-os`, — только то, что относится к ОС: место под «Офис»
и договор между ними.

| Где | Что |
|---|---|
| `devuz-os` (открыт) | служба `devuz-svc-office` (quadlet, без прав, только чтение, в `devuz-ui.slice`), вход через Caddy, сокеты «Ядра» и PostgreSQL, база и каталог данных «Офиса», заглушка «Офиса» для тестов, экран «Состояние» (неделя 8) |
| закрытый репозиторий «Офиса» | экраны (рабочий стол, заявки, сообщения, чат с ИИ, документы, команда), логика из студии (`syanie/app`, `lib/ai-staff/engine.ts`), Telegram-бот, сборка подписанного образа |

## Договор ОС ↔ «Офис» (v1)

- Образ «Офиса» — подписанный нашим ключом контейнер (та же политика, что у
  служб). В открытую сборку ОС он **не попадает**: на коробку приходит
  отдельно (подписанный образ в `/var/lib/devuz/images`, обновляется своим
  каналом). Без образа служба не стартует (`ConditionPathExists`), ОС
  работает как раньше.
- Слушает `127.0.0.1:8100` (HTTP); наружу — только через Caddy
  (`https://devuz.local/` → «Офис»; `/v1/` и сокеты наружу не выходят).
- «Ядро» — через сокет `/run/devuz/core/core.sock` с токеном приложения
  `office` (задачи `chat`, `chat-uz`, `embed`; приоритет `live`).
- PostgreSQL — через сокет `/run/devuz/postgres`, своя роль и база
  `office` (вход `peer`: пользователь контейнера = роль).
- Данные — `/var/lib/devuz/office` (файлы, загрузки); секреты каналов
  (токен бота) — `/etc/devuz/office/` (0600), в образ и репозиторий — никогда.
- Выход в интернет — только к `api.telegram.org` (бот, опрос `getUpdates`:
  коробка за NAT, входящих соединений не нужно). Всё остальное — без сети.
- Здоровье — `GET /api/health` → 200; под сторожем (`devuz-svc-*`).

### Договор v2 (05.11.2026) — что изменилось

- **Выход в интернет из «Офиса» — по списку.** Контейнер работает с
  `Network=host`, фильтра в ОС пока нет, поэтому список ведём здесь, а
  «Офис» пишет журнал исходящих. Разрешено:
  - `api.telegram.org` — бот;
  - `graph.facebook.com` — WhatsApp, Instagram, Messenger напрямую через
    Meta, неделя 7;
  - сервисы push: `fcm.googleapis.com`, `*.push.apple.com`,
    `updates.push.services.mozilla.com`, `*.notify.windows.com` — неделя 8;
  - **госпорталы — только проверка доступности**, без данных клиента:
    `my.soliq.uz`, `my3.soliq.uz`, `didox.uz`, `faktura.uz`,
    `my.mehnat.uz`. Это «Сроки и порталы», этап 2.
- **Всё остальное** (операторы ЭСФ, карты, банки) — только новой записью в
  этом договоре.
- **«Состояние коробки».** В `/run/devuz/status/box.json` новое поле
  `power`: `{"state":"none"|"line"|"battery"|"low","charge","runtime_s","model"}`.
  Его пишет ИБП-служба ОС `devuz-ups`; при смене состояния файл
  обновляется сразу, а не раз в минуту.

### Договор v3 (05.11.2026) — речь в текст

- **Задача `stt` в «Ядре»** (этап 4): у токена `office` она есть.
  `POST /v1/audio/transcriptions?model=stt&language=ru|uz|en|auto`, тело —
  сам файл записи (OGG/Opus, как голосовые Telegram и WhatsApp, WAV, MP3,
  FLAC), до 50 МБ. Ответ: `{ text, language, duration, segments: [{ start,
  end, text }] }`. m4a и видео не принимаются: их «Офис» просит сохранить в
  MP3 или WAV.
- Очередь у речи своя: длинная запись совещания не держит чат. Для
  протоколов «Офис» шлёт `X-DevUz-Priority: staff`, для голосовых
  клиентов — `live`.

## Решения на старте

- Экраны «Офиса» собираем заново, простыми, для клиента; из студии берём
  логику, а не панель (`app/admin` завязана на Supabase — `02-architecture.md`).
- Без сборщиков и npm-пакетов: Node 22 + обычный HTML/CSS/JS, как у
  `syanie/app`, — меньше зависимостей, быстрее на слабой коробке.
- Шрифты — свои файлы в образе (без Google Fonts: коробка работает без
  интернета).
- База — PostgreSQL коробки (не SQLite): одна база, одна копия (неделя 7).
